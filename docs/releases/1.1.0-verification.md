# DuoDeck 1.1.0 verification checkpoint

Observed on 9 November 2026. This checkpoint covers the second redesign, following the request for a clearer, more native experience informed by MagicInterview. Provider records remain authoritative for distribution state.

## Product and source

The website now leads with “Control your Mac from your iPhone or iPad.” It uses Instrument Sans, white and grey surfaces, one blue action color, a plain wordmark and a usable browser preview. Setup is three steps and the download area explains that both native apps are required. Trackpad size applies when the device is held upright.

The native apps use system lists, forms, navigation, menus and semantic colors. iOS starts with Macs and a visible Add Mac action. The working screen keeps Apps, Keyboard, Shortcuts and Settings accessible, with detailed options on their own settings pages. A new installation starts with the Medium trackpad and a hidden optional shortcut row; explicit saved choices are retained. Apps with several windows open a clear window list.

The Mac uses General, Devices, Streaming and Advanced settings groups, a shorter menu, native quality choices and details disclosures. Existing saved settings routes remain supported. Its packaging records the current SDK before signing, preserving the macOS 14 deployment target, and compiles the icon as a current native asset catalog.

The paired-D artwork is shared by both native app icons and the website. The Mac menu uses a matching template glyph. Permission prompts, connection refusals, locked-session text, virtual-display labels and keychain-error fallback copy use DuoDeck. Existing protocol identifiers and keychain storage names remain compatible. Original Sill license and attribution remain intact.

The design direction and reusable execution prompt are in [PRODUCT_BRIEF.md](../PRODUCT_BRIEF.md).

Publish the exact new Mac artifact only after Apple returns Accepted, its tickets are stapled and validated, Gatekeeper accepts it, and the public download bytes match the checksum. Then submit the existing iOS review draft and confirm its submitted date and state. A ready draft is not a sent review request, and submission is not approval or public availability.
